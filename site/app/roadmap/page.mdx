# Roadmap

Kora is being built in small, runnable steps. This page separates the features
implemented in the current codebase from the work that remains.

## Working now

The current codebase includes:

- Python-like syntax, static types, modules, imports, and source diagnostics.
- `kora run`, `check`, `test`, `audit`, `trace`, and durable run commands.
- Typed `analyze` calls with OpenAI and Ollama providers, including images
  and per-call model selection.
- Record and replay cassettes for deterministic tests without model costs.
- Agents, parallel work, lexical budgets, human pauses, and resumable runs.
- Durable pipelines: `fs.write`, `fs.append`, and `sql.execute` are journaled
  effects, so a killed run resumes without writing any row twice, and reads
  are digest-checked so a resume against changed input stops rather than
  mixing two inputs into one run. The journal is append-only, one line per
  effect, and a run is locked to one process while it is open.
- Concise workflow composition: `stream` for a prose answer, `else (why, kind)` for flat outcome handling with a recorded status, and `case A(x) | B(x)` for shared branches.
- Crash-safe streaming inside a durable run. A stream killed after part of its
  answer was written is never sent to the provider again and never writes those
  pieces twice: the resume returns `Failed` for the program to match on. One
  killed before it wrote anything is sent again like ordinary unfinished work.
- One effect lifecycle across model calls, tools, and writes. An effect that
  cannot be repeated safely leaves a mark before it is sent, so a resume can
  tell "never started" from "outcome unknown" — and an interrupted tool-using
  call stops the run naming what is in doubt instead of silently running every
  tool a second time.
- Classified data, scoped `declassify`, sink policies, and audit output.
- Safe terminal output: `print` and `write` redact classified leaves using a project-configurable marker.
- Native `json`, `csv`, `fs`, `http`, `sql`, `time`, `re`, `env`, `notes`, and
  `pdf` modules, with `fs.image` and `fs.glob` for working over a folder of
  files. `pdf` reads a document's text and keeps its page boundaries, and says
  whether there is a text layer at all, so a scan is never mistaken for an
  empty document.
- Package helpers: a package may declare one separate program it carries
  heavy work out to, for what cannot be written in Kora. Kora links no native
  code itself, so a crash or a hang in a helper is a value the program
  matches rather than a dead run. A fetched helper is pinned by `sha256`,
  fetched only for the platform and only for a package the program imports,
  and recorded in `kora.sums`.
- Python sidecar and MCP tool integrations through project configuration,
  with a deadline on every MCP request. A tool server that does not answer
  comes back as `Failed(reason)` instead of ending the run, and tool calls are
  never retried, because a timeout is exactly when whether the effect ran is
  unknown.
- VS Code syntax highlighting, file icons, language-server features, and run
  and test commands.
- Lexical `with context(...)` policies that bound model input independently of
  spend budgets, retaining newest whole tool exchanges and failing rather than
  silently truncating base prompt or data.

## Coming next

### Stabilize streaming and workflows

Streaming prose works for a single `str` call, including inside a durable run,
and is metered and retried on the same terms as a blocking one. The remaining
work is streaming alongside tools and `parallel for`, exact in-flight token
enforcement, and a general event-stream API.

### Fill the deliberate standard-library gaps

`yaml` has shipped: config is where a program is one step from doing
something consequential, so it refuses a duplicate key, reads the YAML 1.2
core schema (no Norway problem), and meters alias expansion against a node
budget so a "billion laughs" file is a value rather than an out-of-memory
kill.

`xml` and a dedicated `network` module remain unbuilt. The existing `http`
module stays the network boundary until a narrower, safer API is ready.

PDF *rendering* is not a stdlib gap any more, and deliberately not a stdlib
feature: it lives in the `pdf_render` package, which carries PDFium in a
helper process. A program that never renders a PDF downloads nothing and pays
nothing for it.

### Complete the package ecosystem when there is demand

A hosted checksum log begins when third parties routinely fetch Kora packages.
WASM components begin when a package cannot be expressed in Kora, MCP, or the
Python sidecar. Native shared libraries remain deliberately unsupported.

### Raise durable write throughput

Every journaled write costs two `fsync`s, which caps a pure-write pipeline near
a hundred rows a second. The fix is group commit across `parallel for` workers,
amortizing one sync over many branches, rather than a weaker guarantee.

### Improve distribution and editor workflows

The next product work includes crates.io and Open VSX distribution, CLI polish,
and richer project-aware editor and debugging workflows.

## A note on status

Kora is still pre-alpha. A feature listed as working is implemented in the
current repository and release checks. A feature listed as coming next is a
real direction, but its APIs may still change.
