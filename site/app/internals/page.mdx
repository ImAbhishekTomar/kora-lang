# Internals

Kora is a tree-walking interpreter built around durable execution, information-flow
labels, and token budgets — not a generic scripting VM. This page traces the
pipeline from source text to a running agent, then the runtime mechanisms behind
[Decisions](/decisions) that don't show up in a typical language.

## The unique parts

<div className="internals-grid">

<div className="internals-card">
  <h3>Journal — durable execution by replay</h3>
  <p>No stack snapshot. Every effect (model call, tool result, human answer, clock read) is appended to a journal on disk. Resuming = re-running from the top, effects served from the journal instead of re-executed, fast-forwarding to where it stopped.</p>
  <div className="internals-why">Why: a Rust call stack can't be serialized — Temporal / Restate solve durability the same way.</div>
</div>

<div className="internals-card">
  <h3>Labels — information flow tracking</h3>
  <p><code>classified</code> values carry a secrecy tag (Public / Classified) and a trust tag (Unverified / Trusted). Labels are transitive: survive slicing, formatting, arithmetic, container insert, return values.</p>
  <div className="internals-why">Why: one line of laundering breaks the whole model — this killed Perl taint mode and Ruby $SAFE.</div>
</div>

<div className="internals-card">
  <h3>Declassify blocks — auditable release</h3>
  <p><code>audit.rs</code> statically enumerates every <code>declassify ... for sink:</code> site in a program, its imports, and its packages — exhaustively, not via grep.</p>
  <div className="internals-why">Why: makes "what data reached the model" answerable to a reviewer, not best-effort.</div>
</div>

<div className="internals-card">
  <h3>Budgets — tokens as the unit of control</h3>
  <p>Budgets are denominated in tokens, the thing the runtime can actually measure, not money. They nest: a child scope can only tighten a parent's limit. Exhaustion is a returned value, never an exception.</p>
  <div className="internals-why">Why: partial agent work should survive running out of budget, not crash.</div>
</div>

<div className="internals-card">
  <h3>Cassettes — record/replay for model calls</h3>
  <p>Three modes: Live, Record (call + append to disk), Replay (never call — a missing entry is an error). Keys cover call site, model, prompt, and resolved input.</p>
  <div className="internals-why">Why: deterministic, free CI without touching a real provider.</div>
</div>

<div className="internals-card">
  <h3>Portable values — the agent isolation boundary</h3>
  <p>Runtime values use <code>Rc</code> for cheap in-agent sharing, so they can't cross threads as-is. <code>Portable</code> is an explicit deep, Send-safe copy used only when values move between agents.</p>
  <div className="internals-why">Why: agents share nothing — isolation is paid for explicitly at the boundary, not assumed.</div>
</div>

<div className="internals-card">
  <h3>Images as values</h3>
  <p><code>fs.image(path)</code> returns a first-class value like <code>fs.read</code> does for text, and flows into <code>analyze()</code>. Type is sniffed from magic bytes, never the file extension; size is checked at read time, not at the provider.</p>
  <div className="internals-why">Why: most real agent work is receipts, screenshots, and forms — not plain text.</div>
</div>

<div className="internals-card">
  <h3>Telemetry — labels guard the exporter too</h3>
  <p>Spans are emitted by the scheduler itself (it already owns every model call, budget meter, declassification) as raw OTLP/HTTP JSON, no SDK. A classified value cannot become a span attribute.</p>
  <div className="internals-why">Why: prompt leakage into observability vendors is a live incident category.</div>
</div>

<div className="internals-card">
  <h3>Modules — one file, one namespace</h3>
  <p>A module is one Kora file (<code>use "./lib/tax.ko" as tax</code>). Its top-level names live in their own namespace, so two files can reuse a name without colliding, and a function always reads the file it was written in. Import paths resolve relative to the <em>importing</em> file, never the working directory.</p>
  <div className="internals-why">Why: a program stays a directory that can be moved or vendored whole.</div>
</div>

<div className="internals-card">
  <h3>Notes — a durable run's own scratch space</h3>
  <p>A key-value store scoped to one durable run (<code>.kora/notes/&lt;run-id&gt;.json</code>), for state a plain variable can't hold: it survives a crash, and a different <code>kora</code> invocation can read it. A <code>classified</code> value written through <code>notes.write</code> keeps its label on the way back out.</p>
  <div className="internals-why">Why: long tool loops already keep a plan and partial results in locals — those shouldn't die with the interpreter.</div>
</div>

<div className="internals-card">
  <h3>Debugger — a zero-cost hook</h3>
  <p>The interpreter knows nothing about DAP. It keeps a frame stack and asks a <code>Debugger</code> whether to stop before each statement — one <code>Option</code> check, no snapshot, when nothing is attached. The editor-facing protocol lives entirely in <code>kora-dap</code>.</p>
  <div className="internals-why">Why: debuggability shouldn't tax every run that isn't being debugged.</div>
</div>

<div className="internals-card">
  <h3>Config — unknown keys are not an error</h3>
  <p><code>kora.toml</code> sections for budgets, sinks, and telemetry parse today even though only model settings are used — Phase 2 ignores keys it doesn't need yet instead of rejecting them.</p>
  <div className="internals-why">Why: a config written now keeps working as later phases start reading more of it.</div>
</div>

</div>

## Package security

<div className="internals-grid">

<div className="internals-card">
  <h3>Capabilities — no ambient authority</h3>
  <p>A dependency reaches the network, filesystem, a database, the environment, a Python worker, or an MCP server only where the importing program granted it (<code>net</code>, <code>fs</code>, ...) — and it can never pass on more than it holds itself.</p>
  <div className="internals-why">Why: in most package ecosystems a dependency runs with the program's full rights, so one compromised package compromises everything.</div>
</div>

<div className="internals-card">
  <h3>Checksum log — trust-on-first-use, permanently</h3>
  <p>A lockfile can't protect the fetch that creates it. The first time a commit is seen, its hash is recorded forever in two logs — the project's committed <code>kora.sums</code> and a machine-wide log under the user's home directory — and every later fetch is checked against both.</p>
  <div className="internals-why">Why: closes publish-a-backdoor-then-delete-it, which leaves no trace in a lockfile alone.</div>
</div>

</div>

| Attack | Stopped by |
| --- | --- |
| Maintainer force-pushes a tag | `lock.rs`: commit/hash mismatch → refuse |
| Repo history rewritten | `hash.rs`: content hash won't follow it |
| Publish backdoor, then delete it | `sumlog.rs`: hash recorded permanently, deletion doesn't erase the record |
| First-time fetch, nothing local to check against | `sumlog.rs` machine-wide log: another project already recorded this commit |
| Compromised dep tries to phone home / read disk | `grants.rs`: no capability granted, no ambient authority |
| Compromised dep re-exports secrets to its own deps | `grants.rs`: can't pass on more capability than it holds |
